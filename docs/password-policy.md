# パスワードの文字種と C-01 の対応

2026年11月9日、C-01に対してローカルコードを修正した。本番への反映・本番での受入確認は別途必要。

登録・管理者再設定・本人変更・ログインで共通の文字種検証を使う。許可範囲は印字可能ASCII（U+0020～U+007E）：半角英数字、記号、半角スペース。日本語、全角文字、アクセント付き文字、絵文字、タブ、改行等の制御文字は拒否する。パスワードの文字を自動で置換・削除しない。

管理者による登録・再設定は従来どおり12文字以上で大文字・小文字・数字・記号を必要とする。本人変更は8文字以上で大文字・小文字・数字を必要とする。これらは新しいパスワードの強度条件であり、既存パスワードによるログインには適用しない。本人変更では現在のパスワードの照合も行う。管理者編集時にパスワードが空欄なら変更しない。

実装は `App\Rules\PrintableAsciiPassword` を共用し、登録・変更で拒否する文字をログインでも同じように拒否する。本人の現在パスワードには新規パスワードの強度条件を適用しない。

検証は業務DBから隔離したSQLiteのメモリDBで実施した。関連Feature 39件・286アサーション、既存Unit 38件・53アサーションが通過。登録→ログイン、管理者再設定→ログイン、本人変更→再ログイン、禁止文字の保存拒否と保存値不変、各登録・変更リクエストの文字種を確認した。PostgreSQL本番環境での検証ではない。

既存の保存済みパスワードはハッシュのため文字種を直接判別できない。既に禁止文字を使用してログインできない利用者には、管理者が許可文字でパスワードを再設定する。既存ユーザーのパスワードを一括変更しない。

設計書v1.3のC-01 OPENは修正前の状態を示す履歴である。本記録はローカル実装と試験の完了を示し、本番の解消や受入完了は示さない。
