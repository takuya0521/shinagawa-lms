# テストコードのコメント記述基準

## 目的

テストコードを初めて読む担当者でも、コードを追う前に「何を確認するテストか」「どの条件で何を実行するか」「何をもって成功とするか」を把握できる状態を維持します。

## テストクラス

各テストクラスには、そのクラスが扱う機能範囲と主要な検証観点を日本語で記載します。

## テストメソッド

各テストメソッドのPHPDocには、次の4項目を記載します。

1. テストの目的を表す日本語の概要
2. `前提:` テストデータ、ログインユーザー、設定値など
3. `処理:` HTTPリクエスト、サービス呼び出し、モデル操作など
4. `期待結果:` レスポンス、表示内容、データベース、例外、権限制御など

実装をそのまま読み上げるコメントではなく、業務仕様と検証意図が伝わる説明を優先します。

## データプロバイダーと補助メソッド

データプロバイダーには各データの意味、補助メソッドには生成するテストデータや共通処理の目的を記載します。複雑な配列を返す場合は、PHPDocの配列形状も残します。

## 品質確認

```powershell
php scripts/check_test_documentation.php
```

Composer経由では次を使用します。

```powershell
composer test-docs:check
```

このチェックは、テストクラス・名前付きメソッドの日本語説明と、テストメソッドの`前提:`・`処理:`・`期待結果:`を確認します。
